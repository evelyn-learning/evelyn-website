# Outreach v2 (Channels + Enrichment) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Per-channel drafts (email / InMail / contact form) with a tabbed Today card, a "Work today" bring-back, and vendor email/LinkedIn enrichment (Apollo→Hunter→Prospeo auto-failover with a monthly credit ledger).

**Architecture:** New `src/lib/outreach/enrich/` provider library (adapter-per-vendor + chain + Mongo credit ledger) consumed by the research pipeline (auto-for-gaps) and a per-lead route. Lead schema gains optional channel-draft and provenance fields — no migration. Today tab card grows channel tabs; Pipeline rows gain Work-today; Find-leads tab shows credit meters.

**Tech Stack:** Next.js App Router, Mongoose 8, `@anthropic-ai/sdk` (existing call layer), house test harness (`npx tsx` + `node:assert`).

**Spec:** `docs/superpowers/specs/2026-08-07-outreach-v2-channels-enrichment-design.md` — the spec's "Owner decisions" section governs any ambiguity.

## Global Constraints

- `emailVerified: true` keeps its strict meaning (server-fetched-and-found, published) — vendor emails are `emailVerified: false`, `emailSource: "vendor"`, `emailProvider` set. Never overwrite a published email with a vendor one.
- Vendor quality floor: store a vendor email only when the vendor itself marks it valid (Apollo `email_status === "verified"`, Hunter `score >= 80`, Prospeo `email_status === "VALID"`). Discard everything else.
- Enrichment must never throw out of `enrichLead` or fail a pipeline candidate; provider HTTP timeout 10s.
- Credit ledger: one credit recorded per provider attempt that returns data; quota-shaped errors (HTTP 402/429, or provider quota message) mark that provider exhausted for the month and the chain continues.
- No live vendor calls in tests (injected fetch/fake providers only). No live Claude calls in tests.
- Client components: values only from `@/lib/outreach/enums` or sibling client files — NEVER `@/models` (guard-enforced).
- All routes session-gate with `getServerSession(authOptions)` before DB access.
- Cadence semantics unchanged (`applyMarkSent`, `expectedNextChannel`, `[1,3,6]d`, max 4 touches, channel-blind counter).
- InMail body target ≤ 500 chars; all three drafts contain the literal `[DEMO_LINK]` line; contact-form draft is self-contained (sign-off with Praveen / Evelyn Learning / praveen@evelynlearning.com since forms don't thread).
- Commit per task; no `--no-verify`.

### Task 3: Provider adapters (Apollo, Hunter, Prospeo)

**Files:**
- Create: `src/lib/outreach/enrich/types.ts`, `apollo.ts`, `hunter.ts`, `prospeo.ts`
- Create: `src/lib/outreach/enrich/providers.test.ts` (chained into `test:outreach-enrich`)

**Interfaces (Produces, in `types.ts`):**

```typescript
export interface EnrichInput { name: string; title?: string; company: string; websiteDomain: string }
export interface EnrichResult { email?: string; linkedinUrl?: string; provider: string; creditsUsed: number }
export interface EnrichProvider {
  name: string;
  isConfigured(): boolean;
  match(input: EnrichInput, fetchFn?: typeof fetch): Promise<EnrichResult | null>;
}
export class QuotaExhaustedError extends Error { constructor(public provider: string) { super(`QUOTA_EXHAUSTED:${provider}`); } }
```

**Adapter contracts (each: 10s `AbortSignal.timeout`, throws `QuotaExhaustedError` on HTTP 402/429, returns `null` on any other error or empty match, never leaks the API key into thrown messages):**
- `apollo.ts`: `isConfigured()` = `!!process.env.APOLLO_API_KEY`. POST `https://api.apollo.io/api/v1/people/match` headers `{ "content-type": "application/json", "x-api-key": KEY }` body `{ name, organization_name: company, domain: websiteDomain, reveal_personal_emails: false }`. From `json.person`: email = `person.email` only if truthy, not matching `/email_not_unlocked/`, and `person.email_status === "verified"`; linkedinUrl = `person.linkedin_url ?? undefined`. Return null if person absent or both fields empty; `creditsUsed: 1` when any field returned.
- `hunter.ts`: GET `https://api.hunter.io/v2/email-finder?domain=${websiteDomain}&full_name=${encodeURIComponent(name)}&api_key=${KEY}`. From `json.data`: email only if `data.email` truthy and `data.score >= 80`. Never returns linkedinUrl.
- `prospeo.ts`: POST `https://api.prospeo.io/email-finder` headers `{ "content-type": "application/json", "X-KEY": KEY }` body `{ full_name: name, company: websiteDomain }`. From `json.response`: email only if `response.email?.email` truthy and `response.email?.email_status === "VALID"` (also accept the flat `response.email` string + `response.email_status` shape — assert both in tests); linkedinUrl from `response.linkedin` if present.

**Tests (injected `fetchFn` returning `new Response(JSON.stringify(fixture), {status})`):** per adapter — happy path, quality-floor rejection (unverified/low-score/INVALID → null), 402 and 429 → `QuotaExhaustedError`, 500 → null, network throw → null, unconfigured `isConfigured()` false when env missing. Set/unset env vars inside tests like `cost.test.ts` does.

- [ ] Steps: failing tests → implement → suites green → commit `feat(outreach): Apollo/Hunter/Prospeo enrichment adapters`.

### Task 4: Enrichment chain

**Files:**
- Create: `src/lib/outreach/enrich/chain.ts`
- Create: `src/lib/outreach/enrich/chain.test.ts` (chained)

**Interfaces (Produces):**

```typescript
export interface ChainDeps { providers?: EnrichProvider[]; ledger?: LedgerOps; fetchFn?: typeof fetch; now?: Date }
export interface ChainOutcome { result: EnrichResult | null; attempts: Array<{ provider: string; status: "hit" | "miss" | "skipped_unconfigured" | "skipped_cap" | "exhausted" }> }
export async function enrichLead(input: EnrichInput, deps?: ChainDeps): Promise<ChainOutcome>
```

Default `providers` = `[apolloProvider, hunterProvider, prospeoProvider]`, default `ledger` = `mongoLedger`. Per provider in order: skip unconfigured; skip if `getUsed >= capForProvider` (record `skipped_cap`); call `match`; on `QuotaExhaustedError` → `ledger.setExhausted` + record `exhausted`, continue; on result → `ledger.addUse(provider, month, result.creditsUsed)`, return `{ result, attempts }` (first hit wins — even if it only has a linkedinUrl and a later provider might have an email: one credit spent is the answer for this round, note in code comment); on null → record `miss`, continue. Never throws.

**Tests (fake providers + in-memory LedgerOps):** first-hit-wins order; unconfigured skipped without ledger touch; at-cap skipped; quota error exhausts + continues to next provider and still hits; all-miss → `result: null` with full attempts trail; ledger increments exactly once per hit; a provider that throws a plain Error is treated as miss (not exhausted).

- [ ] Steps: failing tests → implement → suites green → commit `feat(outreach): enrichment auto-failover chain`.
